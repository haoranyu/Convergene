# Convergene 国际化规范（v0.2）

> 范围：24 小时版本的完整主流程  
> 支持：简体中文、繁体中文、英文  
> 原则：界面可以随时切换，会议内容不会被静默改写。

## 1. Locale

| Locale | 选择器名称 | 人格副标题 | 默认 |
|---|---|---|---|
| `zh-CN` | 简体中文 | 打工人会议作弊器 | 是 |
| `zh-TW` | 繁體中文 | 上班族會議外掛 | 否 |
| `en-US` | English | Your Meeting Cheat Code | 否 |

产品名 `Convergene` 不翻译。语言名称使用自称，不用国旗。三种语言均为 LTR；P0 不承担 RTL。

“完整支持”包括：首页、导览、模型配置、创建、剧本推荐、Grill、准备度、Brief、脑图、节点出招、随手记、会议产出、散会检查、遗忘恢复、报告、错误状态、JSON 导出和数据说明。

## 2. 三种语言状态

### `uiLocale`

全局界面偏好，控制：

- URL locale、导航、按钮、表单、状态、空态和错误；
- Arco 内置组件；
- 日期、时间、数字、列表、复数和人时单位；
- `<html lang>`。

### `contentLocale`

每个 Meeting 独立保存，控制：

- 剧本推荐理由；
- Grill、准备度摘要和 Brief；
- 初始节点、主持人小抄和节点出招；
- 随手记 AI 归类理由；
- 报告的默认输出语言。

创建时默认取 `uiLocale`。切换 UI 不改变它。用户原始输入、手工节点、负责人和专有名词始终保留原文。

### 报告 `locale`

每次报告生成保存自己的 locale 快照，默认取 `contentLocale`，用户可以本次覆盖。重新生成其他语言报告不能修改 Meeting 的 `contentLocale`；旧报告保留到新报告成功。

## 4. 路由与偏好

使用 next-intl App Router，URL 始终带 locale：

```text
/zh-CN/
/zh-TW/meetings/{id}
/en-US/meetings/{id}/report
```

访问 `/` 的选择顺序：

1. `NEXT_LOCALE` cookie；
2. 浏览器语言：`zh-TW`、`zh-HK`、`zh-MO`、`zh-Hant` 映射繁中，其他中文映射简中；
3. 默认 `zh-CN`。

切换语言必须保留 pathname、meeting id、页面阶段、选中节点和查询参数。`NEXT_LOCALE` 只保存界面偏好，与匿名模型 session Cookie 完全分离。

## 5. 消息词典

```text
messages/
├── zh-CN.json
├── zh-TW.json
└── en-US.json
```

命名空间：

```text
common.*
dashboard.*
guide.*
providerConfig.*
meeting.*
meetingMode.*
grill.*
readiness.*
mindMap.*
strategy.*
outcome.*
facilitation.*
report.*
dataStorage.*
errors.*
```

规则：

- 三份词典 key 完全一致，由测试检查；
- 变量、select 和复数使用 ICU message，不拼接半句话；
- 用户可见文字不能散落在 JSX、Zod 错误映射、toast 或 API route；
- `zh-TW` 独立校对，不在客户端进行简繁字符转换；
- 英文优先自然、短促，不逐字翻译中文网络梗；
- 缺失 key 在开发和测试直接失败；生产回退 `zh-CN`，同时记录不含会议内容的 key 名诊断；
- 导览 fixture 的用户内容可以分别准备三语版本，不在运行时调用模型翻译。

## 6. 日期、时间和人时

- 时间戳以 ISO 8601 UTC 保存；
- 显示时使用浏览器时区；报告必须写出时区；
- 日期、时间、数字、列表和复数使用 next-intl formatter 或原生 `Intl`；
- 领域层保存毫秒、整数分钟或原始人数，不保存格式化字符串；
- 人时示例：`1.5 人时`、`1.5 人時`、`1.5 person-hours`；英文必须处理单复数；
- “形成成本估算”不得翻译成精确 monetary cost；英文建议 `Estimated formation effort` 或 `Estimated person-hours to form`，在 UX 校对时保持一致；
- 中文节点按字素边界换行，英文按单词边界换行。

## 7. Arco locale

根 `ConfigProvider` 使用与 `uiLocale` 一致的 locale pack：

```ts
const arcoLocales = {
  'zh-CN': zhCN,
  'zh-TW': zhTW,
  'en-US': enUS,
} satisfies Record<SupportedLocale, Locale>
```

DatePicker、Pagination、Modal、Empty、Upload 等组件不得混用另一语言。若 Arco 某 locale pack 文案不符合产品术语，只在业务组件外层补充 label，不修改依赖源码。

## 8. AI 输出语言

每个任务携带 `outputLocale`。Prompt 必须：

- 要求所有系统生成字段使用目标语言；
- 不翻译被引用的用户原话；
- 允许保留必要专有名词和混合语言引用；
- enum、id、时间和数值保持语言无关；
- 不因 UI locale 切换发起模型调用。

Grill、初始图、节点展开和随手记归类使用 Meeting 的 `contentLocale`。报告使用本次 `outputLocale` 并保存为报告 locale。

若结构正确但大部分说明文字使用错误语言，返回 `OUTPUT_LANGUAGE_MISMATCH`，用户可重试；客户端不能静默机翻修复。

## 9. 布局要求

- 语言选择器显示 `简体中文 / 繁體中文 / English`，不显示国旗；
- 界面语言与会议内容语言使用不同字段名和帮助文案；
- 按钮自适应宽度，不能为中文定死宽度；
- 工具栏空间不足时先收纳次级操作，不能截断开始、结束、保存或提交；
- 节点最多显示两行，完整内容在详情区；
- 英文测试至少使用 40–48 字符节点标题和长错误信息；
- Markdown 表格和 Mermaid 允许容器内横向滚动，页面主体不能整体溢出；
- 手机树状列表必须使用本地化的层级和状态标签。

## 10. 本机保存与云同步文案

三种语言都必须清楚区分：

- 会议数据：当前浏览器 IndexedDB；
- 模型配置：服务端加密 Redis；
- AI 请求：发送到用户选择的 Provider；
- 云同步：P0 尚未提供。

“本机保存”不能翻译成“离线模式”，因为 AI 仍需要联网；“云同步即将支持”不能使用已可用的 CTA 语气。

## 11. 验收

- [ ] 三份 message key parity 通过；
- [ ] 三种 locale 各通过创建到报告主流程；
- [ ] 三种导览 fixture 不调用模型；
- [ ] 剧本、准备度、Strategy、产出和错误枚举全部有三语标签；
- [ ] 语言切换保留会议、阶段和选中节点，不改变 IndexedDB 内容；
- [ ] Arco 内置文案与当前 locale 一致；
- [ ] 模型 Prompt contract 携带白名单 `outputLocale`；
- [ ] 报告 Markdown、Mermaid 和 `.md` 使用报告 locale 的系统标签；
- [ ] 长英文、繁中文字形和 200% 缩放无关键操作截断；
- [ ] `<html lang>`、页面标题和可访问名称正确。

## 12. P0 范围外

- 第四种语言和 RTL；
- 自动翻译用户输入、整张图或既有报告；
- 云端翻译管理平台与翻译记忆；
- 按国家定制币种、税务或工作日历；
- 多语言营销 SEO 页面；
- 运行时简繁转换。
