# ADR 0003：会议剧本与通用会议产出

- 状态：Accepted
- 日期：2026-08-29
- 决策范围：产品信息架构与共享领域原语

## 背景

只做一种通用会议流程会让 Grill、脑图展开和报告显得空泛；为每种会议复制完整产品流程又会增加 24 小时版本的开发量，并造成难以维护的分叉。另一方面，“结论”无法自然覆盖脑暴候选、复盘洞察和行动项。

## 决策

Convergene 使用共享骨架上的四种会议剧本：

- `DECISION`：决策对齐；
- `BRAINSTORM`：脑暴共创；
- `RETRO`：复盘改进；
- `GENERAL`：通用讨论，作为低视觉优先级的兜底。

所有剧本共享 Meeting、Grill、Brief、Node/Edge、Outcome、生命周期、成本算法和报告组装器，只在以下策略层变化：

1. Grill 的准备维度和提问重点；
2. 初始脑图的软模板；
3. 节点旁三张出招卡的 Strategy ID 与 prompt；
4. 默认建议的产出类型；
5. 报告的专属事实段落和图表选择。

AI 可以根据原始需求推荐剧本，但用户必须确认。Grill 开始后剧本锁定；若要更改，必须“重新准备”并清除未完成的准备内容和已生成图。

原“会议结论”统一建模为 `Outcome`，包含四种类型：

- `DECISION`：已确认的选择或约束；
- `CANDIDATE_IDEA`：值得保留但尚未承诺的候选创意；
- `INSIGHT`：对现象、原因或风险的共同认识；
- `ACTION`：可选负责人和截止日期的下一步行动。

Outcome 独立引用任意 Node，而不是改变 Node 的 kind。这样同一节点可以承载产出语义，普通讨论结构也不会被产出类型污染。

## 后果

- 三种主剧本有明显差异，同时绝大部分界面和领域逻辑只实现一次。
- 新增剧本需要补齐完整策略配置、三语词典、AI contract fixture 和报告映射，不能只加一个下拉选项。
- 通用讨论保持可用，但首页入口、推荐和视觉强调均弱于三种主剧本。
- 报告可按 Outcome 类型组织，而不是把所有内容误称为“结论”。
- UI 可以给出轻度卡牌感，但 Strategy 只是上下文操作，不引入游戏经济系统。

## 未选择的方案

- **单一通用模式**：实现更少，但无法形成黑客松需要的完整性、趣味性和清晰价值。
- **每种会议独立应用流程**：体验可高度定制，但重复状态、存储、测试和 UI，24 小时不可控。
- **把剧本做成任意用户 Prompt**：灵活，却无法保证初始复杂度、输出 schema、报告和演示稳定性。
- **继续只用“结论”**：会错误地暗示所有会议产出都是已定事项。
- **把产出做成特殊节点类型**：会把内容层级与产出状态耦合，并阻碍同一节点被重新分类或补充元数据。
