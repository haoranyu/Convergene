# ADR 0001：底层保存图，P0 呈现树

- 状态：Accepted
- 日期：2026-08-28
- 决策范围：会议内容结构与画布呈现

## 背景

会议讨论初期适合用简洁树结构表达，但未来可能出现跨分支的支持、反对、阻塞和关联关系。只保存 `parentId` 能让 P0 更简单，却会让未来加入跨分支关系时发生数据迁移；直接开放一般图又会破坏“初始高度凝练”的产品原则。

## 决策

会议内容底层保存为节点和显式边。P0 只允许创建 `CONTAINS` 边，并强制一个根节点、单父节点和无环，因此用户体验仍是一棵从左到右的单向树。

一级议题通过边上的顺序形成默认会议流程。会议生命周期单独使用状态机，不作为图节点保存。

“当前议题”只允许指向一级议题，是会议流程的游标；“选中节点”是临时 UI 状态。二者不能合并，否则用户查看旁支时会意外推动会议流程。

## 后果

- React Flow 与持久化层使用相同的节点/边表达，不需要互相转换父节点字段。
- P0 比单一 `parentId` 多一张边表和树校验逻辑。
- 未来可以增加跨分支关系，而无需迁移已有节点。
- 在真正实现新关系前，不为每种关系建立界面或模型 prompt。
- 所有模型生成和手工 reparent 都必须经过同一组树不变量校验。

## 未选择的方案

- **只保存 `parentId`**：实现略少，但未来扩展跨分支关系需要迁移。
- **P0 直接开放一般图**：表达力强，但增加理解、布局、生成约束和报告归纳的复杂度。
- **为会议流程另建一张图**：造成内容图与流程图重复；P0 用一级议题顺序已经足够。
