# ADR 0002：会议数据本地优先，模型凭证服务端加密保存

- 状态：Accepted
- 日期：2026-08-29
- 决策范围：数据边界、匿名会话与 BYOK

## 背景

Convergene 是个人会议工具。黑客松版本需要无需注册即可使用、尽量不承担用户会议资料的服务端存储责任，同时又要允许用户在不同页面和刷新后持续使用自己的模型 Key。把 Key 放在 `localStorage` 会暴露给任何成功执行的同源脚本；把会议全部放在服务端则会迅速引入账号、权限、同步和隐私复杂度。

## 决策

P0 使用明确的分层边界：

- Meeting、Node、Edge、Outcome、Report 和 Grill 内容只保存在当前浏览器的 IndexedDB；
- 服务端 Redis 只保存模型 Provider 配置，不保存会议内容；
- 用户不登录也可使用，服务端通过随机匿名设备会话的 HttpOnly Cookie 找到配置；
- Redis key 使用 session token 的哈希，记录使用 AES-256-GCM 加密，30 天滑动过期；
- API 永不返回原始 Key，日志、埋点和错误不得包含 Key 或完整模型响应；
- 默认只允许 StepFun 和硅基流动的固定 Base URL；高级设置只能覆盖白名单规则内的模型 ID；
- 清除模型配置不删除本地会议，清除本地会议不声称已清除服务端模型配置；
- P0 提供完整 JSON 导出，注册登录与云同步是 P1，并且迁移必须由用户显式确认。

## 安全约束

1. `APP_ENCRYPTION_SECRET` 只通过部署环境变量提供，不提交仓库。
2. Cookie 至少设置 `HttpOnly`、`Secure`、`SameSite=Strict` 和限定 Path。
3. 保存、测试、删除配置的写请求执行同源检查和限流。
4. 自定义 Base URL 在 P0 被拒绝，避免 SSRF 和任意凭据外送。
5. Provider 测试失败不得覆盖已有可用配置。
6. 加密、Redis 或 session 失效时返回稳定错误码，让会议的非 AI 功能继续可用。

## 后果

- 用户能匿名开始，刷新后仍可使用自己的模型配置。
- 会议资料不跨设备同步，清浏览器数据会丢失；首页必须持续展示“本机保存”和导出入口。
- 服务端仍持有加密凭据，因此必须认真处理 secret 轮换、日志和 Redis 访问控制。
- 匿名 Cookie 丢失后，旧 Redis 记录只能等待 TTL 清理，不能由用户重新找回。
- P1 云同步需要新增身份、授权、冲突解决和显式迁移方案，不能假装是 P0 的小改动。

## 未选择的方案

- **Key 与会议都放 `localStorage`**：开发最少，但 Key 更容易受 XSS 和第三方脚本影响，结构化会议数据也不适合 localStorage。
- **Key 只放内存**：安全边界简单，但每次刷新都要重新配置，演示和普通使用体验差。
- **加密 Cookie 携带完整 Key**：避免 Redis，却增加 Cookie 体积、轮换和每次请求携带敏感载荷的问题。
- **所有数据直接服务端保存**：会把黑客松项目变成账号与企业数据系统，超出产品定位。
- **系统提供公共 Key**：产生费用、滥用和配额风险，也违背每位用户 BYOK 的共识。
