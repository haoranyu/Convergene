# Convergene 24 小时产品规格（v0.4）

> 状态：产品共识已确认，等待实现  
> 日期：2026-08-29  
> 交付目标：一条完整、可玩、可真实使用的个人会议工作流

## 1. 产品摘要

Convergene 是帮助会议新手的“私人会议作弊器”。它先识别用户要开的是什么会，再用模式化 Grill 把模糊需求问清楚；会前生成一张高度凝练的会议图和主持人小抄；会中由用户在节点上主动“出招”、聚焦议题、随手记录并标记会议产出；会后生成带人时估算的 Markdown/Mermaid 报告。

产品不监听会议，不替用户宣布结论，也不要求团队采用一套系统。它的价值是让一个普通职员在没有主持经验时，也知道会前要问什么、会上卡住时怎么继续、散会前必须留下什么。

## 2. 问题与目标用户

### 核心用户

临时被要求组织或主持会议、但缺少系统方法的普通职员，包括第一次主持跨团队讨论的新人、需要把老板模糊要求变成议程的执行者，以及希望避免无效会议的个人用户。

### 核心问题

- 收到的会议要求往往只有一句模糊原话；
- 不知道这场会究竟应该拍板、发散还是复盘；
- 会前容易遗漏决策人、判断标准、事实材料和最低产出；
- 会中讨论卡住时缺少可立即调用的思考手段；
- 会后有很多记录，却没有明确产出或可交付报告；
- 普通会议工具偏向组织协作，而不是帮助一个人把会主持好。

## 3. 目标与成功标准

### 用户目标

1. 用户在 5 分钟内从老板原话得到可编辑 Brief、准备度和受控脑图。
2. 没有主持经验的用户能够按照当前议题和小抄完成开场、推进与收口。
3. 用户在讨论卡住时，用一次节点出招获得 2–4 个相关、可控的新方向。
4. 用户能明确留下会议产出，并在结束后立即获得可交付报告。
5. 用户理解数据和模型凭证分别保存在哪里，不被迫注册账号。

### 黑客松演示成功

- 无 Key 用户能在 90 秒导览里看到三种剧本的关键差异；
- 真实用户能完成“配置模型 → 创建 → Grill → 脑图 → 开始 → 聚焦 → 出招 → 标记产出 → 结束 → 报告”；
- 能同时展示至少三个处于不同状态的本地会议；
- 报告至少包含一张由真实结构化数据生成的 Mermaid 图；
- 简体中文、繁体中文和英文均能完成主路径；
- 页面刷新后本地会议状态、节点和报告不丢失；
- 模型失败不能破坏已有会议数据。

## 4. 产品原则

1. **新手先于专家**：默认流程直接给建议，高级设置后置。
2. **人主动、AI 响应**：不监听、不自动移动节点、不自动宣布产出。
3. **先凝练、后展开**：初始图小而清晰，复杂度只能通过明确操作增长。
4. **剧本有差异、底层要复用**：模式改变引导策略，不复制业务系统。
5. **产出是事实源**：报告只能把用户标记的内容视为正式结果。
6. **状态与时钟分离**：计划时间负责提示，点击开始和结束记录真实过程。
7. **估算必须诚实**：人时是近似解释，不包装成财务成本或精确归因。
8. **个人优先**：不引入团队、成员、权限和审批。
9. **有梗但不胡闹**：人格文案可以轻松，关键操作与隐私说明必须准确。
10. **三种语言都是完整产品**：国际化覆盖功能、模型输出和报告，不只翻译导航。

## 5. 会议剧本

### 5.1 剧本矩阵

| 剧本 | Grill 重点 | 初始图软模板 | 会中出招 | 主要产出 | 报告专属内容 |
|---|---|---|---|---|---|
| 决策对齐 `DECISION` | 决策人、候选方案、判断标准、信息缺口、风险 | 待决问题、候选方案、判断标准、风险 | 补备选、查风险、逼近决策 | 决策、行动项 | 最终决策、选择依据、放弃方案、风险 |
| 脑暴共创 `BRAINSTORM` | 挑战目标、目标对象、限制、期望数量、筛选方式 | 挑战目标、目标对象、限制条件、探索方向 | 再野一点、换个视角、收敛候选 | 候选创意、洞察 | 创意分组、入选候选、待验证假设 |
| 复盘改进 `RETRO` | 复盘范围、事实、原本预期、影响、期望改进 | 预期与事实、原因、影响、经验与改进 | 追根因、找反例、转成行动 | 洞察、行动项 | 差异、原因链、经验、改进行动 |
| 通用讨论 `GENERAL` | 目标、参与角色、材料、限制、最低产出 | 目标、议题和必要上下文 | 开脑洞、往下拆、反方挑战 | 四类均可 | 只使用公共报告底座 |

软模板不是固定栏目。模型可以合并、改名或省略，但初始图必须说明它覆盖的会议准备重点，并遵守复杂度约束。

### 5.2 选择与锁定

1. 用户先粘贴原始会议需求；
2. AI 返回推荐剧本、建议标题和一句判断理由；
3. 用户确认或改选；三个主剧本突出展示，通用讨论放在次级入口；
4. 用户进入 Grill 后剧本锁定；
5. 如果需要更换，必须使用“重新准备”，清空已有 Grill 和脑图后重新开始。

## 6. 用户故事

### 第一次主持会议的人

- 作为会议新手，我希望系统判断这更像哪种会议，并解释原因，从而不需要先理解方法论术语。
- 作为会议新手，我希望看到当前准备度和具体缺口，从而知道是否还值得继续被追问。
- 作为主持人，我希望当前议题被居中放大并看到一句启动问题，从而不会在复杂画布中迷路。
- 作为主持人，我希望在讨论卡住时能对一个节点打出明确的思考动作，从而快速推进而不让 AI 接管会议。
- 作为主持人，我希望散会前得到收口提醒，从而避免聊完却没有任何产出。

### 个人效率用户

- 作为个人用户，我希望会议数据只保存在自己的浏览器，从而无需注册或把内部会议上传到产品后端。
- 作为个人用户，我希望使用自己的模型 Key，从而控制额度和供应商。
- 作为个人用户，我希望导出完整 JSON 和 Markdown 报告，从而能带走数据。
- 作为可能长期使用的人，我希望清楚看到当前是本机保存，并知道未来可以通过登录开启云同步。

### 高级用户

- 作为高级用户，我希望覆盖 StepFun 或硅基流动预设中的模型 ID，从而测试更适合自己的模型组合。
- 作为英文或繁中用户，我希望界面和 AI 输出都使用所选语言，同时不改写我的原始输入。

## 7. 端到端用户流程

### 7.1 首次打开与导览沙盒

首页没有真实会议时显示两个主操作：“新建会议”和“体验 90 秒导览”。

导览规则：

- 使用内存 fixture，不写 IndexedDB；
- 无需配置模型 Key；
- 可在决策、脑暴、复盘三个示例之间切换；
- 节点出招播放预置结果，不发模型请求；
- 展示分支聚焦、主持小抄、会议产出和报告；
- 离开即清除；
- 用户可点击“以这个示例开始”，此时才复制为自己的本地会议。

### 7.2 模型配置

首次创建真实会议或触发真实 AI 操作时打开配置流程：

- 选择 StepFun 或硅基流动；
- 输入 API Key；
- 默认模型由应用配置；
- “高级设置”允许覆盖当前供应商的 Grill、快速任务和报告模型 ID；
- 不允许输入任意 Base URL；
- 用户必须先测试连接，成功后才保存；
- 系统没有统一公共 Key。

设置页显示当前供应商、连接状态、更换、清除和安全说明。原始 Key 在保存成功后不能再次显示。

### 7.3 创建会议与剧本推荐

用户输入：

- 老板原话或原始会议需求；
- 计划开始与结束时间；
- 预计参会人数；
- 会议内容语言，默认当前界面语言；
- 可选标题，未填写时由分类任务建议。

AI 推荐剧本后，用户确认并进入 Grill。分类失败时保留输入并允许重试或手动选剧本。

### 7.4 Grill 与准备度

Grill 一次只显示一个问题。每轮返回：

- 下一问；
- 为什么要问；
- 已确认摘要；
- 仍缺失的准备维度；
- 当前准备度级别与分段状态。

共同覆盖目标、期望产出、参与角色、信息依赖、限制和最低可接受结果；剧本增加第 5 节定义的专属维度。

轮次规则：

- 默认最多主动追问 5 轮；
- 第 5 轮后若仍有致命缺口，模型可追加一个带理由的“临门一问”；
- 用户随后可以点击“继续拷问我”，每次增加一轮，总上限 10；
- 用户可以点击未完成的准备分段，要求优先追问该方向；
- 用户随时可以回答、不知道、跳过或结束 Grill；
- 准备度不是门禁，信息不足时仍允许生成 Brief。

### 7.5 Brief 确认与初始图

Grill 完成后生成可编辑 Brief，明确区分：已确认、合理假设、仍待确认。

用户点击“确认并生成脑图”后：

- Brief 锁定为准备快照；
- 模型按剧本软模板生成初始图；
- 由程序校验后才写入数据库；
- 新图失败时保留 Brief 并允许重试；
- 会前需要改变方向时，只能通过“重新准备”确认清空图并返回 Grill；
- 会议开始后不能重新准备。

初始图硬约束：一个目标根节点、3–5 个一级议题、最多两层、最多 12 个节点、标题最多 48 个 Unicode 字素、不自动递归展开。

同时生成主持人小抄：一句开场白、每个一级议题的启动问题、议题过渡提示和散会前提醒。

### 7.6 会议首页与状态

首页按以下优先级分组：

1. 正在进行；
2. 待开始；
3. 会前筹备；
4. 已结束。

卡片显示剧本、标题、计划时间、人数和状态。进行中额外显示真实时长、当前议题与累计人时。

多个会议可以存在，但同一浏览器同时只能有一个 `LIVE`。开始新会议时若已有 `LIVE`，用户只能返回上一场或明确结束上一场，系统不能静默结束。

### 7.7 会中工作台

点击开始时确认实际参会人数并记录 `startedAt`。工作台包含：

- 固定顶部状态栏：真实计时、计划剩余/超时、人数、累计人时、当前议题；
- 左到右会议树；
- 当前议题分支聚焦；
- 当前议题主持人小抄；
- 选中节点旁的三个模式化出招；
- 右侧节点详情与会议产出操作；
- 底部随手记。

当前议题只在一级议题间移动。切换时用 200–300ms 平滑 pan/zoom 将该分支居中，其他分支降低视觉权重；用户可以“一览全图”或“重新聚焦”。普通节点选择不改变当前议题。

每次节点出招只携带 Brief 摘要、剧本、所选节点及必要近邻，返回 2–4 个新节点。AI 不负责布局、删除、移动、标记产出或修改已有内容。请求失败时保留原图并允许原地重试。

### 7.8 随手记与 AI 归类

用户按 Enter 后，记录立即挂到当前议题下，不等待模型。随后 fast 模型异步建议一个父节点和最多两个候选位置：

- 建议范围限定在当前议题子树、根节点和停车场；
- 用户接受后才改变父子边；
- 用户可以忽略或选择候选；
- 没有 Key、请求失败或用户离线时，记录仍保持原位；
- 没有当前议题时，记录挂到根节点并提示稍后整理。

### 7.9 会议产出

用户在右侧详情点击“收进会议产出”，系统根据剧本预选类型，但允许改为决策、候选创意、洞察或行动项。

- 会中标记记录 `markedAt`；
- 行动项可选填写负责人和截止时间，均为自由文本/日期，不关联账号；
- 用户可以取消标记，取消需要确认；
- 模型不能自动标记；
- 成本按领域模型确定性计算。

### 7.10 散会检查、结束与遗忘恢复

点击“结束会议”先打开散会检查：

- 已标记产出数量和类型；
- 停车场与未决问题数量；
- 缺少负责人或截止时间的行动项；
- 实际时长、超时和总人时；
- 没有产出时给出明显警告，但允许二次确认后结束。

确认后冻结 `endedAt` 并进入 `ENDED`。

如果用户再次打开应用时发现计划结束后仍有 `LIVE`：

- 按计划结束时间结束；
- 填写实际结束时间；
- 确认会议仍在继续。

真实结束时间必须处于实际开始和当前时间之间，任何选择都不能由模型代替。

### 7.11 模式化报告

报告公共底座：

- 会议目标和剧本；
- 计划与实际时间、时区；
- 实际参会人数、总人时和是否超时；
- 会议产出及各项形成成本估算；
- 未归属人时；
- 停车场与仍待解决问题；
- 下一步，只能使用图中已有信息。

再加入第 5 节定义的剧本专属章节。程序从结构化数据生成最多三张 Mermaid 图，模型只润色事实草稿，不直接写任意 Mermaid。报告提供渲染预览、查看源码、复制 Markdown、下载 `.md` 和选择其他输出语言重新生成。

### 7.12 会后修正

- 默认以只读报告为主；
- 节点文字、行动负责人和截止时间仍可修正；
- 会后新标记的产出注明“会后补记”，不计算形成成本；
- 取消会中产出需要二次确认并重算成本；
- 时间只能通过专门的修正操作修改；
- 已结束会议不能重新进入 `LIVE`。

### 7.13 本机保存与长期转化

应用顶部持续显示“本机保存”。点击后显示：

- 会议数据仅存在当前浏览器；
- 模型配置在服务端加密保存，但不包含会议内容；
- 导出全部会议数据为版本化 JSON；
- 清除本机会议数据；
- “登录并开启云同步（即将支持）”的未来入口。

P1 注册后，本地数据只能在用户明确确认后上传，不能因登录静默迁移。

## 8. 优先级

### P0：必须完成的演示闭环

- 三种主剧本和通用兜底；
- AI 推荐类型、模式化 Grill、准备度和 5＋1＋用户续问；
- Brief 确认与受控初始图；
- 左到右画布、分支聚焦和模式化节点出招；
- 主持人小抄和基础随手记；
- 多会议、唯一 `LIVE`、计时、人时、会议产出和散会检查；
- 模式化 Markdown 报告和至少一张确定性 Mermaid；
- 三种 locale；
- 用户 BYOK、匿名设备会话和模型配置管理；
- 本地 IndexedDB、JSON 导出和无 Key 导览沙盒；
- Vercel 在线演示。

### P0 stretch：尽量完成，按顺序后移

1. 高级模型 ID 覆盖；
2. 手机端树状会议操作；
3. 随手记 AI 归类建议；
4. 会后补记与时间修正界面；
5. 忘记结束恢复向导。

### P1：登录与长期使用

- 注册登录；
- 云端会议存储和跨设备同步；
- 本地到云端的显式迁移；
- JSON 导入与冲突处理；
- 任意 OpenAI-compatible 供应商；
- 历史会议模板与复用；
- 议题级聚焦计时和更精确成本。

### P2：未来探索

- 多人实时协作和权限；
- 日历、Teams、Zoom、飞书集成；
- 会前材料与历史会议知识检索；
- 从行动项进入长期任务跟踪；
- 会议效果复盘和个性化 Grill；
- 语音或转写，但必须重新评估隐私与产品原则。

## 9. 明确不做

- 实时录音、自动听会和发言人识别；
- 让模型自动推进议题或宣布会议产出；
- 团队成员、邀请、评论、权限和审批；
- 人员中途进出和精确考勤；
- 薪资、币种或财务成本；
- 复杂游戏经济、抽卡、积分或胜负；
- 中心放射式自由脑图和任意跨边关系；
- P0 任意 Base URL 模型代理；
- 切换界面语言时自动翻译用户内容；
- P0 把会议内容上传服务端；
- 用不可用的云同步入口假装功能已经上线。

## 10. 边界与失败行为

- 分类失败：允许重试或手动选择剧本；
- Grill 失败：保留所有回答和当前准备度；
- 初始图 schema 不合法：最多自动修正一次，再向用户报错；
- 节点出招失败：删除 loading 占位，不改变原图；
- AI 归类失败：随手记保留原位；
- 报告模型失败：显示确定性事实草稿；
- Mermaid 失败：显示对应数据表和源码，不阻塞正文；
- Redis 不可用：会议仍可查看和编辑，AI 操作提示模型配置暂不可用；
- IndexedDB 不可用：阻止创建真实会议，允许导览，并明确提示浏览器限制；
- 没有任何会议产出：允许结束，报告明确写“本次未标记正式产出”。

## 11. 成功指标

### 24 小时验收指标

- 主演示路径一次通过，无需刷新或手工改数据库；
- 三个主剧本各有一组稳定 fixture 和一条 AI contract 测试；
- 初始图约束、状态机、人时和唯一 `LIVE` 有单元测试；
- 三种 locale 词典 key 完全一致；
- 定向展开目标中位响应时间不超过 3 秒，5 秒内提供明确等待或重试状态；
- 免费托管和数据库额度足以完成现场演示，不要求参赛者付费。

### 上线后的领先指标（P1 观察）

- 首次访问用户中完成导览的比例；
- 导览后开始创建真实会议的比例；
- 创建会议后到达 `MAP_READY` 的比例；
- `LIVE` 会议中至少使用一次节点出招和标记一次产出的比例；
- 已结束会议中成功生成报告的比例；
- 点击“登录并开启云同步”意向入口的比例。

P0 不引入第三方行为分析 SDK；黑客松阶段通过本地演示和人工测试验证，避免为指标增加隐私与实现成本。
