# Convergene UI 设计说明（v0.3）

> 产品人格：帮助会议新手的私人会议作弊器  
> 组件系统：Arco Design React  
> 界面方向：高密度、清晰、可控、略带卡牌趣味  
> 完整工作台：桌面 1024px 以上

## 1. 设计原则

1. **先告诉用户下一步**：新手不应先理解复杂方法论，再知道该点什么。
2. **脑图是主角**：会前与会中优先保证画布空间，辅助内容分层出现。
3. **有梗的是文案，不是关键操作**：开始、结束、删除、隐私和成本必须直白。
4. **可玩但不是游戏**：节点操作可以像轻卡牌，但没有牌组、资源、稀有度或胜负。
5. **显式触发镜头和 AI**：不突然移动画布，不自动改图，不偷走焦点。
6. **稳定的数据反馈**：计时、人时、准备度和产出数不能抖动或夸张动画。
7. **三种语言同等可用**：英文长文案是宽度压力测试，繁中使用独立词典。
8. **本机保存必须看得见**：用户随时知道会议数据没有云同步。
9. **一套组件语言**：通用组件全部使用 Arco Design，不混入另一套组件库。

## 2. 全局信息架构

```text
/{locale}/                         会议首页
/{locale}/guide                    导览沙盒
/{locale}/meetings/new             创建与剧本确认
/{locale}/meetings/{id}/prepare    Grill / Brief / 初始图
/{locale}/meetings/{id}            会前或会中工作台
/{locale}/meetings/{id}/report     会后报告
/{locale}/settings/model           模型配置
/{locale}/settings/data            本机数据与导出
```

实现可以把 prepare/workspace 合并为同一路由下的阶段渲染，但 URL 与浏览器返回行为必须可预测。

## 3. 应用外壳

桌面顶部固定包含：

- `Convergene` 品牌；
- 当前页面标题或会议标题；
- “本机保存”状态按钮；
- 模型连接状态；
- `简体中文 / 繁體中文 / English` 语言切换器；
- 设置入口。

“本机保存”应稍显眼但不制造危险感：使用带设备图标的中性色 `Tag`/Button。点击打开数据说明抽屉，而不是用 toast 一闪而过。

模型状态：

- 未配置：中性描边“配置模型”；
- 可用：绿色图标＋供应商名称；
- 失效：琥珀警告“模型需要重新配置”；
- 请求中：只在触发位置显示 loading，不让全局状态持续闪烁。

## 4. 首页

### 4.1 空状态

```text
┌─────────────────────────────────────────────────────┐
│ Convergene                 本机保存  模型状态  语言 │
├─────────────────────────────────────────────────────┤
│                                                     │
│      把老板原话扔进来，先看看这会到底要干嘛。       │
│                                                     │
│          [ 新建会议 ]   [ 体验 90 秒导览 ]          │
│                                                     │
│      决策对齐 · 脑暴共创 · 复盘改进                 │
└─────────────────────────────────────────────────────┘
```

“新建会议”是主按钮；导览为 secondary。不要自动打开模型配置。

### 4.2 多会议

按“进行中／待开始／会前筹备／已结束”分组。会议卡显示：

- 剧本图标与名称；
- 标题；
- 计划时间；
- 人数；
- 生命周期/时间状态；
- 准备阶段或准备度；
- 进行中时显示实际时长、当前议题和累计人时。

卡片主点击打开会议，更多菜单提供导出单场、复制和删除。删除必须 `Popconfirm`，并说明只删除当前浏览器数据。

如果存在超时仍 `LIVE` 的会议，在所有分组之前显示恢复 banner，不允许普通通知把它覆盖。

## 5. 导览沙盒

导览不是会议列表中的真实记录。

```text
┌─────────────────────────────────────────────────────┐
│ 90 秒导览        决策对齐 | 脑暴共创 | 复盘改进    │
├─────────────────────────────────────────────────────┤
│ 步骤 2 / 5                                          │
│ [提示说明]           示例画布／产出／报告           │
│                                                     │
│ [上一步] [下一步]             [以这个示例开始]     │
└─────────────────────────────────────────────────────┘
```

- 三个场景使用内存 fixture；
- 节点 AI 操作播放预置展开，并标注“示例结果”；
- 步骤覆盖：类型差异、Grill 准备度、分支聚焦、节点出招、产出与报告；
- 退出导览不弹保存确认；
- “以这个示例开始”明确说明将复制到本机会议；
- 导览可随时跳过，不强制完成。

## 6. 模型配置

首次需要 AI 时使用 `Modal`，设置页使用完整 `Card + Form`。

字段：

- 供应商：StepFun（推荐）、硅基流动；
- API Key：password input，禁止浏览器密码管理和拼写检查；
- 高级设置折叠区：Grill / 快速任务 / 报告 model id；
- “测试连接并保存”主操作；
- 安全说明：配置加密保存于服务端，30 天不活跃后删除，会议内容不存服务端。

状态：测试中、成功、认证失败、限流、网络失败、未知模型必须分别给出可行动信息。保存成功后清空表单中的 Key，不提供“显示原 Key”。

已配置状态只展示供应商、模型覆盖、最近使用时间、重新配置和清除。清除使用二次确认，但不删除本机会议。

## 7. 创建与剧本确认

创建表单使用页面或大 `Modal`：

- 老板原话 `Input.TextArea` 是视觉主字段；
- 计划时间 `DatePicker.RangePicker`；
- 预计人数 `InputNumber`；
- 内容语言 `Select`；
- 可选标题。

AI 分类完成后展示三个主剧本卡和次级通用入口：

```text
AI 判断：这更像一场「决策对齐」
因为：你需要在三个方案中形成明确选择。

[✓ 决策对齐] [脑暴共创] [复盘改进]   更多：通用讨论

                                  [确认，开始拷问]
```

剧本卡包含一句效果说明，不列出方法论术语。用户改选后理由不需要重新生成。

## 8. Grill 与准备度

页面采用左侧对话、右侧准备度：

```text
┌──────────────────────────────────┬──────────────────┐
│ 第 3 轮 · 决策对齐               │ 开会准备度       │
│                                  │ ███░░ 勉强能开   │
│ 谁拥有最后拍板权？               │                  │
│ 为什么问：没有决策人，这场会…    │ ✓ 会议目标       │
│                                  │ ◐ 判断标准       │
│ [回答输入框___________________]   │ ○ 决策人         │
│ [不知道] [跳过]        [提交]    │ ✓ 限制条件       │
│                                  │                  │
│ 已确认 / 假设 / 未知             │ [优先问决策人]   │
└──────────────────────────────────┴──────────────────┘
```

- 一次只突出一个问题；
- 准备度进度条按维度分段，不显示百分数；
- 每个分段同时有图标/文字状态，不能只靠颜色；
- 点击未完成维度意味着下一轮优先追问它；
- 第 6 轮“临门一问”使用琥珀色标识并显示理由；
- 默认轮次结束后显示“生成 Brief”和“继续拷问我”；
- 用户续问时显示 `7 / 10`，到 10 后隐藏继续按钮；
- 浏览器刷新恢复历史和当前问题。

## 9. Brief 确认

使用可编辑的结构化卡片：

- 会议目标；
- 期望产出；
- 已确认；
- 合理假设；
- 仍待确认；
- 主持人开场建议。

主操作为“确认并生成脑图”。确认文案必须说明：生成后 Brief 锁定；需要改变方向只能重新准备并清空图。

生成过程中保留 Brief 可见。失败后显示错误和重试，不返回空画布。

## 10. 会议工作台

### 10.1 桌面布局

```text
┌──────────────────────────────────────────────────────────────────┐
│ 返回  标题 · 决策对齐   18:32 / 剩余 11:28   6人 · 1.85人时   │
│ 当前议题 2 / 4：判断标准            [一览全图] [结束会议]       │
├────────────────────────────────────────────┬─────────────────────┤
│                                            │ 主持人小抄          │
│       当前分支居中、其他分支弱化           │ “我们先确认…”       │
│                                            ├─────────────────────┤
│             React Flow 画布                │ 当前节点            │
│                                            │ 详情 / 编辑         │
│       [补备选] [查风险] [逼近决策]         │ 收进会议产出        │
│                                            │ 停到停车场          │
├────────────────────────────────────────────┴─────────────────────┤
│ 上一议题    [随手记，Enter 立即记下________________]   下一议题 │
└──────────────────────────────────────────────────────────────────┘
```

### 10.2 分支聚焦

- Active Topic 使用更强边框、图标和标题；
- 切换议题时对该一级节点及其子树执行 `fitView`；
- 非当前分支降低透明度，但仍可点击；
- 用户手动 pan/zoom 后不自动吸回；
- AI 新节点出现时只做局部淡入，不自动重跑全图；
- “重新聚焦”恢复当前分支，“一览全图”显示完整图；
- reduced motion 下直接跳转镜头。

### 10.3 节点出招

选中节点后，在节点邻近处出现三张紧凑 action card：

- 卡片显示图标、短名称和一行效果；
- 不是永久挂在每个节点上；
- 点击后卡片进入 loading，当前节点下方显示 2–4 个骨架节点；
- 成功后骨架替换为真实节点；
- 失败后移除骨架并在原位提供重试；
- 右侧详情仍负责编辑和产出，避免浮动工具过载。

不要使用翻牌、稀有度边框、能量数字或大幅弹跳。卡牌感来自形态和“出招”文案，不来自额外系统。

### 10.4 随手记

- 输入框固定在画布底部，不能被右侧栏遮挡；
- Enter 创建，Shift+Enter 是否换行可在实现时选择；P0 单行即可；
- 创建成功后立即清空输入并显示新节点；
- AI 归类完成后节点旁出现小 suggestion chip：“建议移到：主要风险”；
- 提供接受、忽略和展开另外两个候选；
- 建议不弹 Modal，不中断会议；
- 用户关闭建议后不重复请求。

### 10.5 会议产出

右侧操作“收进会议产出”打开小型选择区：

- 决策；
- 候选创意；
- 洞察；
- 行动项。

系统按剧本预选，但用户确认。行动项选中后展开可选负责人和截止时间。成功标记后节点增加图标、文字标签和边框变化，不能只变颜色。

取消标记使用 `Popconfirm`；如果会中时间戳将影响其他产出成本，确认文案说明会重新计算。

## 11. 开始、结束与恢复

### 开始会议

确认 Modal 显示计划时间、预计人数和实际人数输入。若已有 `LIVE`，Modal 改为冲突提示，只提供“返回上一场”和“先结束上一场”。

### 散会检查

```text
准备散会？

4 项会议产出
2 个停车场问题
1 个行动项尚未填写负责人
实际 42 分钟 · 超时 12 分钟 · 4.2 人时

[返回整理]                         [确认结束会议]
```

没有产出时使用明显但非危险色的警告：“这场会还没有留下正式产出。”允许二次确认结束。

### 遗忘恢复

应用启动时在首页顶部显示不可忽略的恢复卡：

- 按计划结束；
- 填写实际结束时间；
- 仍在继续。

时间输入必须显示允许范围。任何选项都不使用“智能判断”措辞。

## 12. 报告页

- 默认展示渲染后的 Markdown；
- 顶部摘要显示剧本、产出数、总人时和超时；
- 剧本专属章节紧跟公共摘要；
- Mermaid 图与正文使用相同 token；
- 次级操作：“查看源码”“复制 Markdown”“下载 .md”“重新生成”；
- 输出语言切换放在重新生成动作附近，明确不改变会议内容语言；
- 新报告生成成功前保留旧报告；
- Mermaid 失败时原位置显示数据表和源码，不影响正文；
- 会后补记使用 `Tag` 明确标注且不显示形成成本。

## 13. 本机保存与未来云同步

点击顶部“本机保存”打开 Drawer：

```text
当前：仅保存在这台设备
会议内容不会上传到 Convergene 服务端。

[导出全部数据 .json]
[管理本机数据]

登录并开启云同步
即将支持 · 未来可跨设备保存历史会议
```

- 云同步入口是明确预告，不伪装成已可点击完成的功能；
- 导出是真实可用操作；
- 清除所有本机数据是危险操作，列出会议数量并二次确认；
- 模型配置管理与会议数据管理分成两个区域。

## 14. 手机端边界

### P0 保证

- 会议首页和状态；
- 模型配置；
- Grill 与 Brief；
- 计时、当前议题、主持人小抄；
- 产出查看/标记；
- 报告阅读、复制和下载。

### 不承诺

- 拖拽和自由缩放完整图；
- 节点旁浮动三卡；
- 复杂重新布局。

手机将会议图呈现为按一级议题分组的树状列表。完整画布入口显示“建议在电脑上使用”，但不能阻止用户查看内容。

## 15. 视觉规范

### 颜色

- 主色：深蓝 `#1E40AF`；
- 信息蓝：`#3B82F6`；
- 提醒琥珀：`#D97706`；
- 危险红：`#DC2626`；
- 背景：`#F8FAFC`；
- 卡片：`#FFFFFF`；
- 正文：`#0F172A`；
- 次级文字：`#475569`。

剧本辅助色：决策蓝、脑暴紫、复盘青、通用灰。它们只用于小面积标识；剧本差异必须同时有图标和文字。

### 字体

```css
font-family: Inter, -apple-system, BlinkMacSystemFont, "Segoe UI",
  "PingFang SC", "PingFang TC", "Microsoft YaHei", "Microsoft JhengHei",
  sans-serif;
```

时间和人时可使用系统等宽字体。中文正文不依赖缺少 CJK 字形的 Web Font。

### 密度与动效

- 8px 基础间距，高密度桌面工作台；
- Arco 内置动效＋150–200ms 常规 transition；
- 分支聚焦 200–300ms；
- 新节点淡入并轻微位移；
- 不引入 GSAP；
- 计时数值不缩放跳动；
- 遵守 `prefers-reduced-motion`。

## 16. 文案规则

可以有梗：

- “把老板原话扔进来，先看看这会到底要干嘛。”
- “临门一问：这个问题不确认，会上大概率只能互相看。”
- “再野一点”“逼近决策”“这场会还没有留下正式产出。”

必须严肃准确：

- 开始会议／结束会议；
- 产出形成成本估算；
- 数据发送给所选模型供应商；
- 模型 Key 保存方式；
- 本机保存与云同步状态；
- 删除、清除、时间修正和渲染失败。

## 17. 可访问性底线

- 正文对比度至少 4.5:1；
- 所有键盘焦点可见；
- 图标按钮有可访问名称和 tooltip；
- 常用点击目标至少 44×44px；
- 不能只通过 hover 暴露关键操作；
- 状态、剧本、产出和准备度不能只靠颜色表达；
- 浮动出招工具可以通过键盘到达，Esc 关闭并把焦点还给节点；
- 分支聚焦后不把读屏焦点强制移动到画布内部；
- Mermaid 有标题和数据表降级；
- `<html lang>` 与当前 locale 一致；
- 200% 缩放下仍能完成主操作。

## 18. Arco 组件映射

| 场景 | 组件 |
|---|---|
| 应用外壳 | `Layout`, `Menu`, `Space`, `Typography` |
| 会议卡 | `Card`, `Tag`, `Badge`, `Statistic` |
| 创建/配置 | `Form`, `Input`, `InputNumber`, `DatePicker`, `Select`, `Collapse` |
| Grill | `Steps` 或自定义进度、`Progress`, `Tag`, `Alert` |
| 关键确认 | `Modal`, `Popconfirm` |
| 辅助区 | `Drawer`, `Tabs`, `Descriptions` |
| 反馈 | `Message`, `Notification`, `Spin`, `Skeleton`, `Result` |
| 报告 | `Typography`, `Table`, `Dropdown`, `Button` |

React Flow 节点、浮动出招卡、Markdown 和 Mermaid 容器允许使用 CSS Modules 自定义；不要复制 Arco Button、Input 或 Modal。

## 19. UI 完成检查

- [ ] 三种主剧本能仅凭图标、标题和操作文案区分；
- [ ] 通用模式入口视觉优先级低于三个主剧本；
- [ ] 导览不会污染会议列表和 IndexedDB；
- [ ] 节点出招不遮住相邻节点；
- [ ] 切换议题不会持续抢夺用户画布；
- [ ] 无 Key、模型失败、Redis 失败、Mermaid 失败都有局部降级；
- [ ] “本机保存”在所有主页面可见；
- [ ] 桌面 1024/1440 和手机 375 下主操作无截断；
- [ ] `zh-CN`、`zh-TW`、`en-US` 无缺失文案；
- [ ] reduced motion 和键盘主路径可用。
